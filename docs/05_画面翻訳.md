# 画面翻訳

更新日：2026-11-06

## 方針

画面共有を開始しておき、浮遊ボタンを押したときだけ1枚撮影する。撮影した画像の文字を読み、吹き出し・段落のまとまりごとに日本語へ訳して、元の位置へ重ねる。一般のアプリ画面と漫画を同じ処理で扱う。縦書きを読める漫画用OCRとML Kitを併用し、行ごとに合う結果を選ぶためである（当初の「一般モード・漫画モード」の切り替えは作らなかった。経緯は「判断の記録」）。

1回の翻訳の流れ（`ScreenTranslateService.translateScreen`）：

1. 浮遊ボタンと前の訳を隠し、50ms待って1枚撮る（`ScreenCapturer`）。
2. 文字を読み、まとまりにする（`MultiScriptOcr`。「文字認識」）。
3. 訳す対象を選び、訳の枠の色を撮影画像から読み取る（`selectTargets`。「訳す対象と翻訳」）。ここで撮影画像を捨てる。
4. 空の訳の枠を先に並べ、まとめて訳しながら訳文を流し込む（`BatchTranslator`、`TranslationOverlay`）。

評価用の `BenchActivity` は、文字認識・訳す対象の選別・まとめ訳し（手順2〜4）を実機と同じ関数で行う。評価で測った結果が、実機の画面翻訳の結果と一致するようにするためである。描画だけは画像へ描く別の実装（`BenchActivity.render`）で、枠の広げ方・内側の余白・文字の大きさの範囲は実機と同じ値を使う。評価は画像ごとに訳の控えを作り直すので、控えの効果は測らない。

## 文字認識

`core-ocr` の `MultiScriptOcr` が複数の認識器を並列に動かし、`BlockMerger` が結果をまとめる。返すのは、まとまりごとの文字・位置・文字種・縦書きか（`OcrBlock`）。カメラ翻訳は同じ `MultiScriptOcr` を、まとまりにせず1行ずつ返す設定（`groupLines = false`）と漫画用OCRなしで使う（`docs/10_カメラ翻訳.md`）。

### 使う認識器

| 認識器 | 読めるもの | 役割 |
| --- | --- | --- |
| 漫画用OCR（PP-OCRv6 manga、`MangaOcr`） | 中国語・日本語。縦書きも読める | 中国語・日本語の行は原則これを採る。確信度0.8未満で、ML Kit韓国語がハングルを読めた範囲だけは韓国語に譲る |
| ML Kit 中国語 | 簡体字・繁体字、ラテン文字 | 横書きの中国語。漫画用OCRが無いときは、1文字ずつの位置から縦書きの列を組み直す（`VerticalColumns`） |
| ML Kit 韓国語 | ハングル、ラテン文字 | 韓国語（漫画用OCRは韓国語を読めない） |
| ML Kit 日本語 | 仮名・漢字、ラテン文字 | 日本語の行を見分け、訳さないために使う |
| ML Kit 英字 | ラテン文字だけ | 英語。手書き風の大文字の写植を、他の認識器より正しく読む |

漫画用OCRのモデルは端末の `files/models/ocr/manga/`（`det.onnx`・`rec.onnx`・`dict.txt`）に置く。無ければML Kitだけで動く。漫画用OCRの前処理と復号はモデルカードに合わせ、検出の後処理（しきい値・画素のまとまり・枠の広げ）はOpenCVを使わずKotlinで書いた（APKを大きくしないため）。縦長の行は90度回して横書きとして読む。

### 原文の言語の指定

言語を決めると要らない認識器を動かさず、翻訳でもPLaMoに原文の言語を伝える（`Recognizers`）。自動ではPLaMoが原文から言語を判定する。

| 指定 | 動かす認識器 | 文字認識の時間（1ページ） |
| --- | --- | --- |
| 自動（既定） | すべて | 漫画0.5〜1.0秒、文字の多い画面1.7〜3.1秒 |
| 中国語 | 漫画用OCR＋ML Kit中国語 | 自動とほぼ同じ（漫画用OCRが時間の大半） |
| 韓国語 | ML Kit韓国語だけ | 0.12〜0.19秒。韓国語の漫画1ページの合計は4.0秒→2.0秒（文字認識の短縮は約0.5秒で、残りは翻訳側の差。原因は確かめていない） |
| 英語 | ML Kit英字だけ | 0.13〜0.24秒 |

中国語を指定すると、PLaMoには簡体字（`zh-hans`）として伝える。繁体字の原文は、自動のままのほうが無難である（繁体字の指定は作っていない）。

言語を足すときは、`OcrLanguage`（`core-ocr`）、`Recognizers`、`ScreenLanguage.kt` の表（メニュー名・ボタンの字・PLaMoへ渡す言語）をそろえる。

### 行の選び方とまとめ方（`BlockMerger`）

段落ごとに認識器を選ぶと、日本語の解説に韓国語の引用が混ざった段落で片方の言語が崩れたため（2026-11-05）、行ごとに選んでから、まとまりを組み直す。

1. **縦書きの行を決める**：漫画用OCRの行を採る。採った範囲に重なるML Kitの行（縦書きを横に読み違えた行）は捨てる。韓国語の範囲は残す（確信度が低く、ML Kit韓国語がハングルを2字以上崩れずに読めた範囲）。
2. **行ごとに1つ選ぶ**：位置が重なる行（IoU 0.4以上）を突き合わせ、各認識器が自分の文字をいくつ読めたかで行の言語を決める。

   | 条件 | 採る結果 |
   | --- | --- |
   | 漢字・仮名・ハングルが無い（英語） | ML Kit英字。無ければ、崩れておらずラテン文字を最も多く読めたもの |
   | 仮名が2字以上で、ハングル以上 | 日本語 |
   | ハングルが漢字より多い | 韓国語 |
   | 漢字がある | 中国語 |
   | どれも崩れている（`TextQuality`） | 後段で訳さない |

3. **まとまりに束ねる**（`LineClusterer`）：横書きの行は上下に詰まった行（行間が行の高さの0.8倍未満）、縦書きの列は左右に詰まった列をつなぐ。範囲が2割以上重なる行は形に関係なくつなぐ（重なったまま別の枠に描くと読めない）。仮名を含む行とそれ以外の行はつながない。
4. **読み順に並べる**：縦書きは右の列から、横書きは上の行から。高さの半分以上重なる行は同じ段とみなして左から並べる。

### 縦書き

- 縦書きの判定：高さが幅の1.5倍以上の行。ただし英字だけの行は縦書きとして扱わない（狭い吹き出しで短い単語が縦長になるため）。
- 縦書きの約物は横書きの形に戻して訳へ渡す（`VerticalColumns.normalize`）。Unicodeの縦書き用表示形（U+FE10〜FE19、U+FE30〜FE4F）はNFKCで戻す（UCD 16.0で確認）。横書き用のOCRは縦の破折号「——」を「|」、縦の省略号「……」を「:」に読むので、1字分の高さがあるものだけ置き換える（中国語の縦書きで両者を字面中央に縦に置く規則は W3C clreq 5.1・5.4.1、GB/T 15834—2011）。

### 英語

漫画の写植は全部大文字のことが多い。大文字だけの文を渡すと、翻訳が固有名詞とみなして英語のまま残した（「FINE.」）。そのため `EnglishText` で次のように整えてから訳す。

- 英字の8割以上が大文字なら、文頭と単独の「I」だけ大文字の文に直す。
- 行末のハイフンで切れた語はつなぐ（「COM-」「PARED」→「COMPARED」）。敬称（「NATORI-CHAN」の「-CHAN」など）のハイフンは残す。

## 訳す対象と翻訳

`selectTargets`（`TranslationTargets.kt`）が、まとまりから訳す対象を選ぶ。

- 状態バー（時刻・通信速度など）にかかるまとまりは訳さない。
- 訳先が日本語なので、仮名を含むまとまり（日本語）、数字・記号だけのまとまり、崩れたまとまりは訳さない。欧文は1文字だけなら飛ばすが、漢字・ハングルは1文字でも訳す（漫画の「咦」「嘟」）。
- 行の折り返しをつなぐ。韓国語・欧文は空白で、日本語・中国語は詰めてつなぐ。英文は上の `EnglishText` で整える。

`BatchTranslator` は、まとまりを読み順に最大8行・400文字ずつ改行でつないで1回で訳し、訳文を改行で分けて各まとまりへ戻す。1まとまりずつ訳すと、毎回プロンプト処理の固定費がかかり1画面で20秒を超えたため（2026-11-05）。行数が合わないときは、そのまとまりだけ1つずつ訳し直す。同じ原文の訳は500件まで控え、撮り直したときに使い回す。原文の言語を変えたときと、翻訳モデルを切り替えてエンジンが変わったときは作り直す（`BatchTranslator.reuseOrCreate`。2026-11-06、エンジンを見ずに使い回して、閉じたエンジンで訳し続けて失敗した）。`selectTargets` と `BatchTranslator` はカメラ翻訳も使う（`docs/10_カメラ翻訳.md`）ので、変えるときはカメラ翻訳への影響も見る。

## 訳文の重ね表示

| 項目 | 内容 |
| --- | --- |
| 権限 | `SYSTEM_ALERT_WINDOW`（設定画面で作者が許可する） |
| 窓 | `TYPE_APPLICATION_OVERLAY` の小さな窓を、訳1つにつき1つ置く（全画面の窓だと下のアプリを操作できない）。撮影画像と同じ座標に置くため `fitInsetsTypes = 0`・切り欠き領域も使う設定にする |
| 枠の大きさ | 認識した枠を左右4dp・上下2dp広げ、原文の端を隠す（`OverlayStyle.padded`） |
| 色 | 背景色と文字色を元の画面にそろえる（`ColorSampler`）。背景は枠を少し広げた外周の最頻色、文字は枠の中で背景から十分に離れた画素の中央値。コントラスト比（WCAG）が3未満なら黒か白にする。透けると読みにくいので不透明に塗る |
| 横書き | `TextView` の自動縮小で、枠に収まる大きさ（7〜22sp）にする |
| 縦書き | 縦書きの原文には縦書きで描く（`Tategaki`）。右の列から左へ、句読点は右上に寄せ、長音・ダッシュ・波線・三点リーダーは90度回し、括弧は縦書き用の字形にする（W3C JLReqの縦組みに合わせた）。文字の大きさは横書きと同じ範囲 |
| 表示の順序 | 空の枠を先に並べ、訳し終わった部分から流し込む |

## 評価

### 方法

作者のスクリーンショットを `tools/testdata/ocr/<画面集>/` に置き、デバッグビルドの `BenchActivity` で画面翻訳と同じ処理をかける。漫画など著作物を含むため、画像と結果はGitに入れない（`.gitignore`）。`tools/run-bench.ps1` が、端末への転送・実行・取り出し・採点までを行う。

```powershell
./tools/run-bench.ps1 -Set 2026-11-05 -Label <名前>                 # 自動
./tools/run-bench.ps1 -Set 2026-11-05-en -Label <名前> -Lang ENGLISH  # 言語を指定
```

結果は `tools/testdata/ocr/<画面集>-out/<名前>/` に、画像ごとの所要時間と訳（`results.jsonl`）と、訳を元の位置に描いた画像（PNG、半分の大きさ）として残る。正解（`truth.json`：吹き出しの位置と原文）がある画像は、`tools/eval-screen.py` が次の観点で採点する（作者の希望、2026-11-05）。

| 観点 | 数え方 |
| --- | --- |
| 認識率 | 正解の吹き出しのうち、訳が1つ以上入った割合（セリフを全部認識できたか） |
| 一まとまり率 | 正解の吹き出しのうち、訳がちょうど1つ入った割合（吹き出しを1まとまりで訳せたか） |
| 欠け | 最小の文字（7sp）でも枠に収まらなかった訳の数と、9sp未満の訳の数（重ねた訳に欠けがないか） |
| 文字の正解率 | 正解の原文と読み取った原文の一致の割合（正解に原文があるページだけ） |

漫画用OCRなどの候補をPCで比べるときは `tools/ocr-spike.py`、合成した英語の画面と正解を作るときは `tools/make-en-screen.ps1` を使う（`docs/06_開発環境.md`「画面翻訳の評価」）。

## 判断の記録

| 日付 | 判断 | 理由・根拠 |
| --- | --- | --- |
| 2026-11-05 | 認識器を段落ごとでなく行ごとに選び、まとまりは位置関係で組み直す | 段落ごとだと日韓混在の段落で片方が崩れた。漫画2ページの一まとまり率が35%→100% |
| 2026-11-05 | 縦書きの原文は縦書きの日本語で描く | 作者の要望。1つの文が複数の枠に分かれて重なり読めなかった |
| 2026-11-05 | 縦書きを読める漫画用OCRを足す（作者決定「足す」）。PP-OCRv6 mangaを採る | ML Kitは縦書きの中国語の字を読み落とした。PCで比べた文字の正解率（下表） |
| 2026-11-05 | 一般モード・漫画モードの切り替えは作らない | 漫画用OCRとML Kitを併用し、行ごとに選べば一般の画面と漫画を同じ処理で扱えた。当初案のcomic-text-detector・manga-ocrは採らなかった |
| 2026-11-05 | 言語は自動判定を既定にし、浮遊ボタンの長押しで指定もできる | 作者の要望。自動判定は1ページ0.4〜0.8秒多くかかり、その大半は漫画用OCRの時間だった |
| 2026-11-05 | 訳の枠の色を元の画面にそろえる | 作者の要望 |
| 2026-11-06 | ML Kitの英字専用の認識器を足す | 作者の指摘「英語の吹き出しの検知と翻訳が良くない」。中国語の認識器は手書き風の大文字を「TITN」「PK YRO OOT RK」と読み違えた。前日は合成画面だけで「中国語の認識器で十分」と判断していた |

縦書きを読めるOCRの比較（2026-11-05、PCで `tools/ocr-spike.py`、中国語版3ページ・吹き出し31個の文字の正解率）：

| ページ | ML Kit | PP-OCRv6 manga | PP-OCRv5 mobile |
| --- | ---: | ---: | ---: |
| 4/30（吹き出し13） | 75.7% | 97.4% | 94.1% |
| 7/30（吹き出し10） | 42.9% | 84.5% | 61.9% |
| 8/30（吹き出し8） | 16.2% | 93.2% | 91.9% |

PP-OCRv6 mangaは検出1.7MB＋認識20.2MB、Apache-2.0、日本語・中国語用。PP-OCRv5 mobile（検出4.6MB＋認識15.8MB）は英語も読めるが、英語の漫画ではほとんど読めなかった（2026-11-06）。漫画用OCRの確信度は、PCで中国語の行が中央値0.99、韓国語の行は90%点でも0.75だったので、しきい値を0.8にした。

## 残る問題

- 評価画像30枚のうち7枚目（上の表で正解率がいちばん低い1枚）に残る読み違い：スマホ画面内の小さな横書き（「事情结束了？我在楼梯口等你呢」が「肉技口你呪」）。縦の長音「—」、「嘟」の片方の読み落とし。
- 英語の漫画は、作者の実機での確認がまだ。正解も無く、点数で追えていない。
- 英語の漫画を自動判定で読むと、ローマ字の名前の一部を韓国語の認識器がハングルとして拾うことがある（「SHOUTAROU」→「SHO니TARO니」）。英語を指定すると正しく読める。
- 翻訳が、まれに訳文へ別の文字種を混ぜる（「SASA-SHOUTAROU-KUN」→「笹เจ้า太郎くん」。タイ文字が混じった）。原文は正しく読めているので、翻訳側の問題。
